## Scope and enforcement

The machine-readable policy is `lint-exceptions.json`: nine exact issue/path/message tuples, reviewed current/suggested version pairs, Wry version, generated-file SHA-256 fingerprints, reasons and re-review conditions. The two generated files are unmodified upstream output.

`lint-reviewed.xml` scopes the three Kotlin diagnostics to their individual files, and the six version notices to anchored exact-message expressions. Android lint does not combine path and regex selectors as an AND condition. Therefore `scripts/verify-android-lint.py` first runs the same strict lint task with empty `lint-audit.xml` and validates its XML report against exact issue + file + message + severity tuples. New findings in application code, changed version notices, missing/stale findings, duplicate findings, changed Wry version or changed generated bytes fail this audit. Only then does scoped lint run and require zero errors/warnings plus the single known hint.

The reviewed configuration uses a nondefault filename so it cannot be auto-discovered as a parent configuration during the unsuppressed audit. Both configs and the generated-source fingerprints are verified before execution. An expected audit exit code alone is never accepted as success. Logs and both XML reports are preserved in ignored test/build output.

## Reasons, risks and removal conditions

- **DefaultLocale:** accepted only for Wry's diagnostic console formatting. Risk: locale-specific line-number formatting; this approval is not a general correctness exemption. Re-review on Wry or file changes and if diagnostic formatting affects application behavior.
- **UseKtx:** accepted only for the generated bitmap convenience-API suggestion. It does not justify changing pixel size/configuration or bypassing runtime tests. Re-review on Wry or file changes.
- **ViewConstructor:** accepted only for Wry's runtime-created WebView, which needs scripts and a native ID. A dummy constructor could create an invalid runtime. Re-review on Wry/file changes or introduction of XML/layout-tool construction.
- **Six update notices:** retain tested version pins. The detector reports newer versions, not evidence of a vulnerability or incompatibility. These exact reminders stop blocking the reviewed lint pass; dependency/security review remains necessary. Re-review on current/suggested version changes or relevant advisories. Remove when upgraded or the finding disappears.

Source changes fail closed for human re-review; do not refresh fingerprints automatically to silence a gate. No application-authored diagnostic is exempted. See [Android lint documentation](https://developer.android.com/studio/write/lint) and [dependency detector](https://googlesamples.github.io/android-custom-lint-rules/checks/GradleDependency.md.html).

## Browser/WASM boundary

The maintainer explicitly approved moving a minimal real Worker/WASM smoke test into 01. `tools/runtime-probe` compiles real Rust into a separate WASM asset; a browser Worker fetches/instantiates it and calls the probe through a typed, validated bridge. The UI displays the returned result. Missing, corrupt and aborted module loads visibly fail, and retry starts a fresh Worker. There is no TypeScript success fallback.

Shared Nostr logic, encryption, storage conformance, archive interoperability and headless Android JNI remain in 02. The earlier browser-only evidence did not prove WASM execution. Current results belong in `MEMORY/memory.md` and `docs/compatibility.md`.
