# Public foundation fixtures

These are public test data, never application identities or user archives.

`event.json` is generated by `cargo run -p vault-core --example fixture` (nostr 0.45.5, secp256k1 0.30.0). The example uses the explicitly test-only repeated-byte secret 01 and deterministic signing. No signing code is linked into the foundation library. Run the same command with `-- --out-of-scope` to regenerate `out-of-scope.json`, a valid signed kind-0 event deliberately outside this proof's fixed author/kind scope.

`payload.zip` was generated with CPython 3.14.7 standard-library zipfile:

```python
import zipfile
with zipfile.ZipFile("payload.zip", "w", compression=zipfile.ZIP_STORED) as archive:
    entry = zipfile.ZipInfo("fixture.txt", (2020, 1, 1, 0, 0, 0))
    entry.external_attr = 0o100644 << 16
    archive.writestr(entry, b"NostrVault public archive proof\n")
```

SHA-256: `be0ebbf0d9b3bad87fd8d619a1862b62cea8879e549e75b6d2ee03a82aafdcb9`.
The application treats the ZIP as opaque bytes; it has no ZIP importer.

The Argon2id known-answer vector uses password `foundation password`, salt 16 bytes of 01, v19, m=8192 KiB, t=1, p=1, output length 32. Expected output `eaf5c0ecb502e73136524ec0176230e88821873fadbfde2d16567214c9c89a72` was independently generated with libargon2-20190702-10.fc44.x86_64 (libargon2.so.1) `argon2id_hash_raw` through Python ctypes. These parameters are proof-only, not a production password policy.
